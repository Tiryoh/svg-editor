## 1. 概要

### 目的

Illustratorなどの有償ソフトなしに、SVGベクターデータの入稿前チェックと修正をブラウザだけで完結させるWebツール。

### 対象ユースケース

| カテゴリ | 具体例 |
|----------|--------|
| アパレル | Tシャツ・パーカー・キャップへのプリント |
| ステッカー・シール | カッティングシート、ラベル |
| 看板・バナー | イベント横断幕、屋外看板 |
| 印刷物 | 名刺、チラシ、パッケージ |

### 対象ユーザー

エンジニアおよびデザイナー。UIの説明文は最小限でよい（過度な誘導文不要）。  
用語はIllustratorの表記に準拠し、両者が違和感なく使えるようにする。

---

## 2. 用語定義

v3まで独自表記だった用語をIllustrator準拠に統一する。実装コード内の変数名・コメントもこれに合わせる。

| v3までの表記 | v4以降の表記（UI・設計書） | 備考 |
|-------------|--------------------------|------|
| レイヤーをフラット化 | **レイヤーを統合** | Illustratorの「レイヤーを統合」に相当 |

| 小さいパスの削除 | **孤立点・小さいパスを削除** | Illustratorの「オブジェクト → パス → 余分なポイントを削除」に相当 |

| 削除 | **削除**（変更なし） | — |
| なげなわモード | **なげなわ選択**（変更なし） | Illustratorと同名 |

## 4. 機能仕様

### 4-1. SVG読み込み

| 項目 | 内容 |
|------|------|
| 入力方法 | ドラッグ＆ドロップ または ファイル選択ボタン |
| 対応形式 | `.svg` のみ |
| 読み込み後 | プレビュー表示 + インスペクト結果を自動表示 |
| エラー処理 | 非SVGファイル・破損ファイルはエラーメッセージ表示 |
| パフォーマンス警告 | パス数が1000を超える場合に警告バッジを表示 |

---

### 4-2. インスペクトパネル

ファイル読み込み直後に自動実行。クリーンアップ・編集後も随時更新される。

#### ドキュメント情報

| 表示項目 | 取得方法 |
|----------|----------|
| 幅・高さ（px） | `width` / `height` 属性 |
| 幅・高さ（mm） | px値をmm換算（96dpi基準: 1px = 0.2646mm） |
| viewBox | `viewBox` 属性の生値 |
| 総パス数 | DOM走査で集計 |

#### 色パレット

SVG内の全パスの `fill` / `stroke` を走査して一覧化し、色ごとに以下を表示する。

| 表示項目 | 詳細 |
|----------|------|
| スウォッチ | 色の矩形プレビュー |
| HEX値 | `#223B52` 形式 |
| RGB値 | `rgb(34, 59, 82)` 形式 |
| CMYK値 | RGB→CMYK近似変換値。**印刷用参考値**である旨を注記（※） |
| 使用パス数 | その色が使われているパスの件数 |
| 全選択ボタン | その色のパスをすべて選択状態にする |

**（※）CMYK変換についての注記:**  
SVGはRGB色空間で定義されており、CMYKへの変換は近似計算（単純変換式）によるものです。正確なCMYK値が必要な場合はIllustrator等の色管理機能を使用してください。

CMYK変換式（シンプル変換）:

```
R' = R/255, G' = G/255, B' = B/255
K  = 1 - max(R', G', B')
C  = (1 - R' - K) / (1 - K)
M  = (1 - G' - K) / (1 - K)
Y  = (1 - B' - K) / (1 - K)
各値を0〜100の整数で表示
```

表示例：

```
■ #223B52   rgb(34,59,82)    C87 M61 Y31 K47   32パス  [全選択]
■ #E06738   rgb(224,103,56)  C0  M60 Y77 K12   18パス  [全選択]
■ #FFFFFF   rgb(255,255,255) C0  M0  Y0  K0     9パス  [全選択]
─────────────────────────────────────────────────
合計 3色  59パス
※ CMYK値は近似値です
```

`none` / `transparent` は除外する。

#### 孤立点・小さいパス検出

- 全パスのバウンディングボックスを `getBBox()` で取得
- 幅・高さが両方ともしきい値以下のパスを検出
- しきい値はUIで変更可能（デフォルト: 5px）
- 検出件数をバッジ表示
- 「ハイライト表示」「一括削除」ボタンを提供

#### ストローク検出

- `stroke` が設定されているパスの件数を表示
- 件数が1以上の場合、「ストロークのアウトライン化」ボタンをここにも表示

---

### 4-3. クリーンアップ

#### レイヤーを統合

全 `<g>` 要素を解体し、全パスを1階層に並べる。

**処理詳細:**

1. SVG内の全 `<g>` を走査
2. 各パスの `getCTM()` で現在の変換行列を取得
3. パスの座標点に行列を乗算して絶対座標に変換（transform焼き込み）
4. `<g>` タグを除去してパスをフラットなリストに展開
5. ルートに設定された `fill-rule` / `clip-rule` を各パスの `style` 属性に明示的に書き込む

**制約:**

- 実行前に確認ダイアログを表示
  - 「この操作はUndoできません」を明記
  - `fill-rule:evenodd` が設定されている場合、重なり箇所の見た目が変わる可能性がある旨を追記
- **Undoの対象外**

#### 孤立点・小さいパスを削除

- インスペクトで検出されたパスをまとめて削除
- 実行前に「N個のパスを削除します」と件数確認ダイアログを表示
- **Undoの対象**（1操作としてスタックに積む）

#### ストロークのアウトライン化

strokeを持つパスをアウトライン化し、fillパスに変換する。

**処理詳細:**

- **paper.js** を使用してアウトライン化を実行
- 変換後は元の `stroke` 属性を削除し、アウトライン化したパスの `fill` を元の `stroke` 色に設定
- 元のパスの `fill` が `none` でない場合、fillパスとstrokeのアウトラインパスを両方生成

**実装フロー:**

```
SVG文字列 → paper.jsにインポート
→ strokeをアウトライン化
→ paper.jsからSVG文字列をエクスポート
→ 元のSVG DOMを置き換え
```

paper.jsはオフスクリーンのCanvas要素を用意してそこで処理する（プレビューエリアとは分離）。

**制約:**

- 実行前に確認ダイアログを表示（「この操作はUndoできません」を明記）
- **Undoの対象外**
- 複雑なdash patternやmarkerは変換精度が落ちる場合がある。変換後に目視確認を促すメッセージを表示

---

### 4-4. 手動編集

#### 選択モード

**クリック選択**

- パスをクリックして選択
- 選択中パスはアウトラインでハイライト表示
- `Shift + クリック` で複数追加選択
- キャンバスの空白部分クリックで選択解除

**なげなわ選択**

- ドラッグで自由な選択範囲を描く
- ドラッグ中は半透明オーバーレイで範囲を表示
- 範囲に重なる全パスを選択
- 確定後もShiftクリックで追加選択可能

#### 操作パネル（選択中に表示）

**色変更**

| 機能 | 詳細 |
|------|------|
| カラーピッカー | 任意の色をフリー選択 |
| プリセット色 | インスペクトの色パレットで検出した既存色をスウォッチ表示してワンクリック適用 |
| 適用対象 | 選択中の全パスの `fill` を変更 |

**同じ塗りを選択**

- 選択中パスの `fill` 色と完全一致する全パスを追加選択
- 色パレットの「全選択」と同等だが、選択済みパスを起点に発動する操作として提供

**削除**

- `Delete` キー または 「削除」ボタン
- 選択中の全パスをDOMから除去
- **Undoの対象**

---

### 4-5. Undo

| 項目 | 内容 |
|------|------|
| ショートカット | `Ctrl+Z`（Windows） / `Cmd+Z`（Mac） |
| 最大ステップ数 | 30ステップ |
| Undo対象 | 色変更・削除・孤立点一括削除 |
| Undo対象外 | レイヤーを統合・ストロークのアウトライン化（確認ダイアログで明示） |
| Redo | V1スコープ外 |

**実装方針:**

操作ごとに変更前の状態（対象要素の `style` 属性、または削除された要素のクローン）をスタックに保存。Undoは逆順で状態を復元する。

---

### 4-6. エクスポート

| 項目 | 内容 |
|------|------|
| トリガー | 「エクスポート」ボタン |
| 出力形式 | `.svg`（編集後のDOM状態を `XMLSerializer` でシリアライズ） |
| ファイル名 | 元ファイル名に `_edited` を付与（例: `logo_edited.svg`） |

## 6. 技術スタック

### 選定方針

ブラウザ完結・Claude Codeで実装・依存を最小にしつつ必要な機能を満たす構成を選ぶ。

### 推奨構成

| 項目 | 選定 | 理由 |
|------|------|------|
| フレームワーク | React + Vite | ブラウザ完結、HMRで開発しやすい、Claude Codeとの相性が良い |
| 言語 | TypeScript | 型があることでClaude Codeの出力精度が上がる |
| スタイリング | Tailwind CSS v3 | ユーティリティクラスで高速実装 |
| SVG操作 | DOM直接操作 | 外部ライブラリ不要 |
| transform焼き込み | `getCTM()` + 行列乗算 | ブラウザAPIで完結 |
| ストロークのアウトライン化 | **paper.js** | strokeアウトライン化の実績あり。CDN経由で読み込み可 |
| ビルド・配信 | Vite build → 静的HTML | サーバー不要、`index.html` をそのまま開ける |

### 状態管理

外部ライブラリ（Redux等）は不要。Reactの `useState` / `useReducer` + `useRef` で管理する。

| 状態 | 管理場所 | 型 |
|------|----------|-----|
| 読み込まれたSVG DOM | `useRef` | `SVGSVGElement \| null` |
| 選択中パスの集合 | `useState` | `Set<SVGElement>` |
| 選択モード | `useState` | `'click' \| 'lasso'` |
| Undoスタック | `useRef` | `UndoEntry[]` |
| インスペクト結果 | `useState` | `InspectResult` |
| ファイル名 | `useState` | `string` |

## 7. 実装上の注意点

### getCTM() によるtransform焼き込み

考慮すべきケース：

1. `<g transform="matrix(...)">` の入れ子
2. `<g transform="translate(...)">` の入れ子
3. SVGルートの `viewBox` によるスケール
4. `<use>` 要素（今回のSVGには含まれないが一般的な注意事項）

`getCTM()` はブラウザがレンダリング済みの累積変換行列を返すため、入れ子の深さに依らず1回の呼び出しで正確な変換行列が取得できる。ただし **SVGをDOMに描画した状態でないと呼び出せない** ため、プレビューエリアへのマウント後に実行する必要がある。

### paper.js の利用

paper.jsはグローバルに `paper` オブジェクトを提供する。Reactコンポーネントとの統合では、Canvas要素を別途用意してpaper.jsに渡す（SVG DOMとは分離したオフスクリーン処理）。

### evenodd / clip-rule の扱い

対象SVGのルートに `fill-rule:evenodd; clip-rule:evenodd` が設定されている。フラット化処理では、ルートのstyle設定を各パスの `style` 属性に明示的に書き込む。

### CMYK変換

`colorUtils.ts` に単純変換式を実装する。ICC profileによる正確な変換はV1スコープ外。変換式は本設計書4-2節を参照。

## 9. 既知リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| `evenodd` によるレイヤー統合後の見た目変化 | 中 | 確認ダイアログに明記。ルートstyleを各パスに書き込む処理を追加 |
| `getCTM()` の精度（浮動小数点誤差） | 低 | 小数点以下3桁で丸める |
| paper.jsのアウトライン化精度（dash pattern等） | 低〜中 | 変換後に目視確認を促すメッセージを表示 |
| CMYK変換の精度 | 低〜中 | UIに「近似値」と明記。ICCプロファイル対応はV2候補 |
| 大容量SVGでのパフォーマンス | 低〜中 | パス数1000超で警告表示。インスペクトの再計算はdebounce（300ms）を挟む |
| クリック選択の重なり精度 | 低 | なげなわ選択と色パレット「全選択」で補完 |
